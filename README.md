# ziyuanAI · ComfyUI 图片与视频节点

连接 `https://ziyuanai.cn`，使用本站 API 令牌。修改后重启 ComfyUI，并刷新浏览器页面。

## 统一视频节点

同一个“ziyuanAI. 视频生成”节点切换以下四个模型；异步模式先执行“视频异步提交”，再用相同 API 密钥执行“视频异步获取”。

| 模型 | 分辨率 | 时长 | 参考图 | 参考视频 | 参考音频 |
| --- | --- | --- | --- | --- | --- |
| omni-flash-components | 720p / 1080p | 1–60 秒，真实服务范围待实测 | 最多14张 | 不支持 | 不支持 |
| doubao-seedance-2.0 | 480p / 720p / 1080p / 4k | 4–15整数秒 | 最多9张 | 最多3段 | 最多3段，每段2–15秒，须搭配图片或视频 |
| doubao-seedance-2.0-mini | 仅720p | 4–15整数秒 | 最多9张 | 最多3段 | 最多3段，每段2–30秒，须搭配图片或视频；上游效果待验证 |
| doubao-seedance-2.5 | 480p / 720p / 1080p | 4–30整数秒 | 全部素材合计最多12个 | 全部素材合计最多12个 | 最多10段，每段2–30秒；可仅音频加提示词 |

2.5 生成时长支持4–30整数秒，普通和异步节点均适用；需要中转站同步支持30秒。已通过本地30秒请求与边界测试，未进行本次付费生成验证。

三个 Doubao 模型的素材总数均不得超过12，包括 IMAGE/AUDIO 批次和远程链接。2.5 仅采用中转文档公布的总数上限，不承诺12段视频一定通过上游容量限制。固定比例：16:9、9:16、1:1、4:3、3:4、21:9；Mini 另支持自动（adaptive）。三个模型均显示“生成声音”开关，默认开启。声音开关控制成片声音，与参考音频能力不同。

已移除 `seedance-2.5v5`、`seedance-2.0-fast-1080p`、`jimeng-2.5-480p`、`jimeng-2.5-720p` 的选择项和适配代码。使用这些旧模型的工作流需要手动选择新模型，不会自动替换后提交。图片模型和图片数量修复保留。

## 图片、视频、音频直接连接

### 统一素材加载与拆分

新增 `ziyuanAI统一素材加载` → `ziyuanAI素材拆分`，位于 `ziyuanAI` 分类。支持上传、拖入或粘贴图片、音频、视频；最多9张图片、3段音频、3段视频。素材卡片可预览、删除和同类排序，工作流保存素材文件名；分享工作流时须同时提供 input 目录中的原素材。

拆分节点按相连加载节点中的实际素材数量自动展开输出，image_count / video_count / audio_count 为只读统计，上传、删除、清空后自动更新，旧工作流中的手动数量不再限制输出。图片为 IMAGE，视频为原生 VIDEO，音频为 AUDIO，可直接连接本插件的参考素材输入。单节点15个槽位不代表模型允许15个素材，仍以所选模型的总数、时长和大小限制为准。未加载的输出默认阻断对应分支，也可选择“允许空值”。

这两个节点独立集成自本地 Chajian 工具箱的素材加载/拆分实现，保留已修复的面板缩放逻辑，不依赖安装该工具箱，也不替换原 CJ 节点。添加后须重启 ComfyUI 并刷新浏览器。

“加载图像”的 IMAGE 输出接“参考图”；原生“加载视频”的 VIDEO 输出接“参考视频”。原生“加载音频（LoadAudio）”的 AUDIO 输出接“参考音频”。需要连接 MiniMax H3 等使用 IMAGE 帧序列作为视频参考的节点时，使用“ziyuanAI视频转参考帧”：最多接入3个 VIDEO，`video_frames_1/2/3` 依次连接 H3 的 `ref_video_0/1/2`，`video_audio_1/2/3` 依次连接 `ref_video_audio_0/1/2`；无原声的视频音轨输出为空，不输出帧率。H3 使用声音参考时还需连接 `audio_vae`；单独上传的音频可从拆分节点直接连接 `ref_audio_0/1/2`。旧工作流加载时自动补齐音轨输出并移除帧率输出，保留已有画面与音轨连线。转换保留原始帧率的帧序列，不做24fps重采样。IMAGE 帧序列须先经“创建视频”转换为 VIDEO。默认只显示各类型第一个空输入口，接入后展开下一个；断开中间连线时，后续素材按顺序前移、连续编号。图片节点沿用相同规则。

切换模型后自动调整分辨率、比例、时长。已有连线保留；不受新模型支持的连线标注“请断开”，后端拒绝执行，避免静默漏掉素材。保存、恢复工作流同步保留素材顺序。

在原“提示词”框输入 `@`，弹出当前节点已连接的素材列表，显示编号、来源节点及可用的文件名；未连接或标注“请断开”的素材不提供选择。可以点击选择，也可以用上下方向键和 Enter/Tab 选择，Esc 关闭；继续输入素材类型或名称可筛选。普通和异步图片/视频节点均支持，提示词中显示 `@图1`、`@视频1`、`@音频1`，兼容手写 `@图片1`。

提交时，插件将这些标记转换为实际上传素材的同类序号描述，例如 `@图2` → `（第2张参考图片）`，与素材一起发送给模型。若第一个 IMAGE 输入含两张图，第二个输入的 `@图2` 则转换为 `（第3张参考图片）`；引用整个批次时使用序号范围，音频批次同理。接口没有独立的 mention-ID 字段，因此采用明确的文字引用，真实模型遵循效果尚未进行付费验证。断开前面的连线时，后续引用跟随原素材重新编号；删除被引用素材会留下 `@已断开(...)`，执行前报错，需删除标记并重新输入 `@` 选择，避免指向另一素材。

Doubao 的“素材模式”有两种：

- 组合参考：按各自编号顺序发送图片、视频、音频；无需素材时即文生视频。
- 首尾帧：参考图1为首帧，参考图2为可选尾帧。最多两张图片，含批次；不得混用视频或参考音频。

图片转换为 PNG，每张最多10 MiB；视频转换为 MP4，每段最多50 MiB、时长大于0且不超过15秒。不会自动裁剪素材。中转站及 Nginx 的总请求体限制仍可能更小。

三个 Doubao 模型均支持本地 AUDIO 连线，转为 PCM 16-bit WAV 后每段最多15 MiB，保留单/双声道和采样率。时长按每个 AUDIO 批次中的每段分别校验，不截短音频；音频时长不改变生成视频的时长。Mini 的旧音频链接接受 HTTPS 或 asset://。旧工作流填写的图片/视频/音频链接保留，并在非空时显示供清理；新工作流直接连素材即可。同类素材不能同时填写旧链接和连接本地输入。2.0/2.5 的旧链接必须是带 expires/signature 的巧模 `/api/reference/` 签名链接。

为兼容旧 Mini 工作流，素材模式及链接字段的内部名称仍以 Mini 开头；界面标签去掉此前缀。超过所选模型上限的已连插口保留并明确报错。首尾帧模式收起空的音频/视频口，已有连线标注需要断开。如果旧节点缺少新控件，请重新添加统一视频节点并接线。

## 中转站要求

这三个模型按 `qiaomo-seedance` **0.4.1** 对接，Mini仅支持720p。旧工作流恢复或切换到Mini时，界面会将不支持的分辨率调整为720p；直接通过API提交Mini 480p会在请求中转站之前报错。本地素材上传需要配套宿主 `qiaomo.go/adaptor.go` 补丁，音频需要0.4.0宿主的 qiaomoAudioUpload 能力。0.4.1的本地部署记录确认JS插件已激活，宿主的定价显示补丁仍待执行；节点按实际请求校验规则限制Mini。本次未修改服务器、渠道或价格。

插件向本站 `POST /v1/videos` 提交：无素材用 JSON；本地素材用 multipart，图片字段 input_reference，视频字段 input_video，音频字段 input_audio（audio/wav），首尾帧用 first_frame/last_frame。比例、分辨率、声音及远程素材放入 metadata；multipart 时 metadata 是 JSON 文本。中转站上传本地文件至巧模 `/v1/assets`，取得签名地址后创建视频任务。

仍需本站模型渠道启用、令牌授权和价格配置完成才能调用；截图中曾显示2.5价格未配置，请以后台当前状态为准。插件不选择售价。上传会占用上游素材配额，不自动重复提交，不另建上传缓存或删除上游素材。

## 节点与异步任务

共9个节点：统一素材加载、素材拆分、视频转参考帧、图片生成、图片异步提交、图片异步获取、视频生成、视频异步提交、视频异步获取。图片模型为 gpt-image-2、gpt-image-2.5-flare、gpt-image-2.5-sunburst、gpt-image-2-super、T香蕉2、T香蕉2.1、T香蕉pro，节点最多接入14张参考图，实际限制以模型接口为准。2026-11-04 七款模型均已完成2K文生图、单参考图、双参考图真实出图；更大参考图数量及高级选项的验收范围见下文。

图片参数包含提示词、模型、比例、分辨率（1K/2K/4K）、质量、输出格式、生成数量及公共设置。图片“自动”比例沿用第一张参考图，无参考图按1:1。质量/格式默认自动，不额外发送参数。

T香蕉2、T香蕉2.1、T香蕉pro 使用原图片生成和异步图片节点。每个任务仅生成1张；切换到这些模型时数量自动设为1，隐藏不适用的质量、输出格式，输出编码由模型决定。支持比例1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9；自动取第一张参考图最接近的支持比例，无参考图用1:1。1K/2K/4K原样作为分辨率传递，不换算成GPT图片像素尺寸。21:9不在本站当前图片转换接口支持范围内。

T香蕉文生图发送 JSON 至 `/v1/images/generations`，参考图发送 JSON 至 `/v1/images/edits`，参数 `size` 为比例、`quality` 为分辨率、`n=1`，参考图按顺序放入 `image`。本站将其转换为 Gemini `generationConfig.imageConfig.aspectRatio/imageSize` 与图片 `inlineData`。随后通过 `/v1/images/tasks/{task_id}` 等待完成并下载结果；兼容标准图片字段及 Gemini 图片结果，不输出处理中预览、不自动重发。`@` 引用沿用上传序号转换。

图片和视频异步获取只需填写提交时使用的同一 API 密钥，不再输入或连接任务编号；留空使用 `ZIYUAN_API_KEY`。先完成整批异步提交，再执行获取；两者没有连线依赖，不保证在同一次执行中的先后顺序。

获取开始时，将同一密钥、同一类型尚未取回的任务固定为一批，按提交顺序等待并输出全部结果。例如连续提交3个图片任务，就取回这3个任务的全部图片；连续提交10个视频任务，就输出10个视频及其对应路径、状态。图片以 ComfyUI 列表输出，每个任务内部的图片批次保持不变，支持不同任务返回不同尺寸，后续预览/保存节点会逐项处理。视频以原生 VIDEO 列表输出，后续节点逐段处理。成功取回后，新提交的任务进入下一批；没有新任务时重复获取复用上一批，不会重新生成。获取过程中追加的任务留到下一批；有任务失败时明确报出本批数量和失败位置，不把部分结果冒充完整批次。请勿用同一密钥、同一类型同时提交希望分开获取的工作流，它们会合并为同一批。

插件仅保留密钥摘要用于匹配，不会查询网站历史任务。最多同时运行2个任务，最多保留32个记录；未获取的结果不会被新提交静默覆盖，达到上限时需先获取结果。已获取记录可能被后续提交淘汰。重启后本地记录失效，应先查网站任务记录，避免重复付费提交。取消获取只停止本地等待，不会取消服务端任务。

异步示例默认禁用获取节点：填写密钥并执行提交后，禁用提交节点、启用获取节点，填写相同密钥后再次执行。

示例在 examples：01-image-and-video.json、02-image-async.json、08-unified-video.json、09-unified-video-async.json。视频示例默认 Mini，可切换模型。安装时务必包含 web 目录。

## 安装

1. 将整个 `comfyui-ziyuan-API` 文件夹放到 `ComfyUI/custom_nodes/` 下。
2. 如缺少依赖，用运行 ComfyUI 的 Python 安装本目录的 `requirements.txt`。Torch 使用 ComfyUI 已安装的版本，不需要另装。
3. 重启 ComfyUI，搜索“ziyuanAI”。视频节点需要支持原生 VIDEO 类型的 ComfyUI；本机 ComfyUI 已确认存在 `comfy_api.input_impl.VideoFromFile`。

例如当前本机整合包的依赖安装命令（先完成复制）：

```powershell
& 'F:\ComfyUI-aki-v3\python\python.exe' -m pip install -r 'F:\ComfyUI-aki-v3\ComfyUI\custom_nodes\comfyui-ziyuan-API\requirements.txt'
```

## 使用

### 图片

“ziyuanAI. 图片生成” → “预览图像”或“保存图像”。输入提示词、API Key，选择模型即可。需要参考图时，把“加载图像”连接到图片输入口。`生成数量` 最大输入值为10。`gpt-image-2` 实测忽略接口的多张数量，因此节点逐张提交 `n=1` 并合并输出，选择几张就创建几个独立计费任务，共用最大等待时间；中途失败立即停止，不自动重发。该批量修复已通过本地普通/异步测试，真实复测受上游额度不足阻挡。其他GPT模型保持单次提交 `n`，数量支持范围待真实验证；T香蕉每任务限1张。

`gpt-image-2-super`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 的参考图使用 `multipart/form-data` 上传至 `/v1/images/edits`：单图为 `image` 文件，多图使用中转站支持的 `image[]` 文件字段。Flare/Sunburst 原JSON上传真实失败，改用文件后四组单/双参考图复测通过。普通和异步节点使用同一上传逻辑；文生图仍使用JSON。Super已真实验证2K文生图和单/双参考图；其他参数与参考图上限仍待实测。

### 视频

“ziyuanAI. 视频生成” → 原生“保存视频（SaveVideo）”节点，可显示视频预览。视频节点已经将下载文件保存到 `ComfyUI/output/ziyuan/`，连接 SaveVideo 会额外保存一份。可连接参考图进行图生视频或多图参考生成。

选择 Omni 时，“比例”和“分辨率”自动换算成 API 的宽高尺寸；“时长秒数”是请求的视频时长。UI 提供的数值范围不是服务能力承诺；尚未通过付费请求核实 Omni 的尺寸、时长和参考图上限。

### 公共设置

- `API地址` 默认 `https://ziyuanai.cn`，也接受以 `/v1` 结尾的地址。
- `API密钥` 填写你网站的 API 令牌。也可以留空，通过启动 ComfyUI 时的 `ZIYUAN_API_KEY` 环境变量提供。直接填写的密钥会随工作流保存，分享工作流前请清空。
- `种子` 仅用于改变 ComfyUI 缓存输入，让同一提示词再次生成。它不发送到模型，也不保证图片复现。需要每次生成时，使用其生成后递增/随机选项。
- `最大等待秒数` 限制本次执行的等待时间。可通过 ComfyUI 的取消按钮停止本地等待；这不会取消服务器已创建的任务，也不会保证退款。
- 提交请求时，连接和参考素材上传使用节点剩余等待时间，等待响应共用该预算，避免大参考图上传被原来的15秒超时提前中断。图片生成节点保留输入参考图的原始尺寸；这项修改不改变上游接口的容量要求。连接中断会显示中文提示，生成请求不会自动重发。
- 请求失败会让节点明确报错。不会输出黑图充当成功结果，也不会自动重发生成请求。超时后请先检查网站任务记录再重试，避免重复计费。
- 单个任务返回的图片尺寸不一致时会报错，不会自动缩放或裁剪；异步获取的不同任务可保留各自尺寸。
